# Карточка рисков ИИ-функции

| Вопрос | Ответ |
|---|---|
| **Категория риска** | Ограниченный риск: система подсказывает, решение принимает человек (пользователь выбирает, сотрудник подтверждает). Не затрагивает права человека напрямую, не запрещённое и не высокорисковое применение. Требуется прозрачность — пользователь должен знать, что работает ИИ |
| **Что происходит при ошибке модели** | Пользователю показано неподходящее животное, или подходящее не показано. Неподходящее отсекают проверка обязательных ограничений (вариант D: правила R1–R14 по подтверждённым полям карточки сильнее мнения модели) и сотрудник при рассмотрении заявки. Пропуск подходящего уменьшает пользу, но не вредит |
| **Худший сценарий** | Модель рекомендует животное, опасное для ребёнка до 6 лет или несовместимое с другим питомцем. Человек подаёт заявку, сотрудник не проверяет, животное возвращают в приют — стресс для животного и семьи. Защита: такие пары помечаются «Недостаточно данных» и не попадают в рекомендации, пока в карточке не подтверждено `yes` |
| **Способ обнаружения** | 1) Eval-набор (36 сценариев) прогоняется при каждой смене модели или промпта. 2) Журнал `recommendation_log`: режим (ai / fallback / disabled), выданные id, время, токены, ошибки. 3) Панель «ИИ-подбор» у сотрудников: доля резервного режима, отказов, конверсия. 4) Заявки с `recommendation_id`, отклонённые сотрудником, — сигнал для ручного разбора |
| **Где человек в контуре** | Пользователь видит объяснение и сам решает, подавать ли заявку. Каждую заявку рассматривает и одобряет только сотрудник (`PATCH /admin/applications/{id}`). Если подобрать безопасно нельзя, кнопка «Передать вопрос сотруднику» создаёт обращение (`/admin/ai/handoffs`) |
| **Как пользователь узнаёт, что работает ИИ** | Над анкетой и над результатами показана надпись: «Рекомендации сформированы с помощью искусственного интеллекта. Совместимость и условия содержания необходимо подтвердить с сотрудником приюта». Ответы помощника в чате помечены значком ✦. Под полем чата: «Не указывайте телефон, адрес и другие личные данные: текст обрабатывается внешним ИИ-сервисом» |
| **Резервный режим** | При недоступности модели: «Облачная модель сейчас недоступна — показан подбор по правилам без ИИ. Совместимость необходимо подтвердить с сотрудником приюта». При отключении: «ИИ-подбор временно отключён — показан подбор по правилам…» |
| **Какие данные передаются провайдеру** | Анкета (жильё, дети, другие животные, время, опыт и т. д. — без имени), текст чата после удаления телефонов и e-mail, карточки кандидатов (порода, размер, совместимость — без фото и описаний). **Не передаются:** ФИО, телефон, e-mail, id пользователя, заявки. Остаточный риск: человек может сам написать в чате личные сведения |
| **Версионирование** | `PROMPT_VERSION` в `backend/recommender.py`, промпты и few-shot сохраняются в каждый прогон (`evals/raw/<run>/prompts/`). Записываются модель, `system_fingerprint` провайдера и версия каталога (хэш `data/animals.json`). Смена любого из них — повторный прогон eval до выкладки |
| **Мониторинг качества** | Еженедельно: доля fallback, отказов и уточнений, среднее время, токены (`/admin/ai/stats`). Ежемесячно: 20 случайных сессий подбора размечает сотрудник, считаем долю нарушений. Конверсия в заявку — бизнес-метрика |
| **Деградация при недоступности** | Таймаут 25 с. Если провайдер просит подождать до 8 с (минутный лимит, HTTP 429), делается один повтор. При любой другой ошибке — подбор по правилам с отдельным уведомлением и точной причиной: лимит запросов, нет ключа, ключ отклонён, нет соединения, пустой ответ. Тип сбоя пишется в журнал. Сайт, каталог и заявки работают независимо от ИИ. Проверено на практике: при исчерпании суточного лимита Groq сайт переключился на правила с причиной «превышен лимит запросов» |
| **Использование данных для обучения** | Мы не дообучаем модели на данных пользователей. Groq по своим условиям не использует данные API для обучения (проверить в условиях на дату запуска). В eval-набор попадают только тестовые сценарии или обезличенные обращения с согласия |
| **Механизм отключения** | Переключатель «Отключить ИИ» в панели сотрудника (`PATCH /admin/ai`, роль admin или owner, запись в журнал действий). Действует сразу, без перезапуска сайта. Аварийно: переменная `AI_ENABLED=0` на Render |
