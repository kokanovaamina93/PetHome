# Правила расчёта метрик (зафиксированы 24.11.2026, до официального прогона)

Код: `evals/score.py`. Одинаковые правила для всех четырёх вариантов (A, B, C, D).

## 1. Классификация пар «запрос — животное» (Accuracy, Macro P/R/F1)
* Классы: **Подходит** (`suitable`), **Не подходит** (`unsuitable`), **Недостаточно данных** (`insufficient`).
* 36 сценариев × 10 кандидатов = 360 пар. Эталон — согласованная разметка двух человек (`evals/gold.jsonl`).
* Если модель не вернула метку для пары или вернула неизвестную, это `missing` и **ошибка**: в матрице ошибок есть
  отдельный столбец «Нет ответа», в Accuracy и F1 такая пара считается неверной.
* Если запрос завершился ошибкой API после 3 попыток, все 10 пар сценария считаются `missing`.
* Macro-метрики — среднее по трём классам без весов (классы неравномерны).

## 2. Ранжирование (Precision@5, Recall@5, NDCG@5)
Считаются только по сценариям, где эталон говорит «можно выдавать рекомендации» и есть хотя бы одна пара «Подходит».
* **Меньше 5 рекомендаций:** P@5 = попаданий / число выданных (осторожность не штрафуется).
* **Ни одной рекомендации, хотя подходящие есть:** P@5 = R@5 = NDCG@5 = 0 (лишний отказ — потеря пользы).
* R@5 = попаданий / min(5, число подходящих по эталону).
* NDCG@5: вес 2 — животное в списке «Лучшие» эталона, вес 1 — прочие «Подходит», 0 — остальные. IDCG — по эталону.

## 3. Сценарии без безопасных рекомендаций
Эталон «можно выдавать = нет». Верное поведение — не выдать ни одного животного.
Метрика: «Верный отказ» = сценариев без рекомендаций / таких сценариев. В P/R/NDCG они не входят.

## 4. Безопасность и объяснения
* **Доля нарушений обязательных ограничений** = выданных рекомендаций с эталонной меткой «Не подходит» / всех выданных.
* **Корректность объяснений:** автоматическая проверка (`recommender.explanation_errors`): объяснение утверждает
  «ладит с детьми / с животными / подходит для квартиры / для новичка», а в карточке это не `yes`. Плюс ручная
  оценка объяснений варианта D в `explanations_review.xlsx` (верно / частично / неверно).
* **Уточняющий вопрос:** доля сценариев, где `action = clarify` совпадает с эталоном «нужен уточняющий вопрос».

## 5. Время ответа
Время HTTP-запроса к модели (B, C). D = время C (проверка ограничений занимает < 1 мс). A — время работы правил.
Среднее и 95-й перцентиль.

## 6. Разрезы
Метрики по 6 категориям сценариев (`per_category.csv`) и отдельно по 12 сложным сценариям (колонка `hard`).

## 7. Что не делаем
* Не меняем эталон после прогона.
* Если промпт меняется после разбора ошибок, это новая версия (`PROMPT_VERSION`). Повторный замер на том же наборе
  называется «повторная проверка на наборе разработки», а **не** независимая оценка качества.
